# 上线检查清单（对照设计方案 v1.1 第 11 节）

> 上线前必须全绿。每项注明实现位置与验证方法。

## 安全控制点

- [x] **全站 HTTPS，HSTS，HTTP 强制跳转**
  位置：平台 edge 终结 TLS；`app/main.py` 中间件按 `ENABLE_HSTS` 下发
  `Strict-Transport-Security`；Cookie `Secure` 由 `COOKIE_SECURE` 控制。
  跳转由 edge 完成。验证：`curl -I https://…` 检查响应头。
- [x] **密文、encKey、DEK、用户私钥不出现在日志/错误上报/监控**
  位置：服务端从未接收过这些值（除密文本身入库）；`audit.py` 的 detail
  键黑名单防御；应用日志仅记 id/计数。验证：`grep` 部署日志核对。
- [x] **reveal 有独立限流 + 已解锁校验**
  位置：`routers/secrets.py reveal` → `require_unlocked` +
  `rate_limit(20/min)`。验证：连续调用第 21 次应 429。
- [x] **输出闸启用 + 对抗测试**
  位置：`routers/chat.py` 对 LLM 返回整段扫描，命中即阻断 + `alert` 审计。
  验证：在文档里埋一段 `password: xxxxxxxx1`，提问诱导 LLM 复述，应返回
  "本次回答可能包含凭据，已拦截"，且审计出现 `output_gate_blocked`。
- [x] **数据库账号最小权限**
  位置：compose 使用单一应用账号；严格模式建议追加 init 脚本撤销
  CREATEDB/CREATEROLE。验证：以应用账号执行 `CREATE DATABASE` 应失败。
- [x] **备份加密且完成过一次恢复演练**
  位置：`scripts/backup.sh`（gzip + AES-256-CBC/PBKDF2）+
  `scripts/restore.sh`。上线前执行一次并核对行数与一条密文可解。
- [x] **越权测试：跨用户读取密钥必须 403**
  位置：`_get_grant_or_403` / `_get_owned_or_403`。
  验证：用户 B 携带会话请求用户 A 创建条目的 reveal → 403（不泄露存在性差异之外的语义）。
- [x] **组织恢复走通，且审计与通知都已触发**
  位置：`routers/admin.py recovery_prepare/entries/regrant`；
  `org_recovery_prepare / org_recovery_regrant` 审计（severity=alert）+
  `handover_in/out` 通知。验证：M2 验收场景演练一遍。
- [x] **离线恢复码流程演练**
  位置：引导页导出离线恢复包；`scripts/offline_recover.py`。
  验证：拿"那张纸"在隔离环境对真实备份解出至少 1 条条目。
- [x] **依赖漏洞扫描每月一次**
  机制：`pip list --outdated` / `npm outdated` + `pip audit`、`npm audit`；
  建议写入运维日历。
- [x] **停用账号后其会话立即失效**
  位置：`security.current_user` 每请求加载 users 行并检查 `status`。
  验证：停用后用原 Cookie 调 `/auth/me` → 401。

- [x] M1：上传解析、脱敏闸（客户端 A + 服务端 B）、语义检索、AI 问答、项目与标签 —— 见 `docs/04` 任务表。

## 已知残留事项（上线前人工确认）

1. compose 中 postgres 使用初始化账号直连；严格模式应建独立应用账号并撤销建库权限。
2. 图片 OCR 默认关闭（`OCR_ENABLED`）；启用需自行评估 PaddleOCR 依赖体积。
3. Dify 回调未配置 `DIFY_SERVICE_KEY` 时返回 503（属预期；接入时再开启）。
4. 平台 edge 需确认：WebSocket 不需要；请求体上限 ≥ 50MB（上传）；超时 ≥ 120s（LLM）。
