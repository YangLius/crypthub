## 真实环境联调记录（2026-11-10）

环境：远程 PostgreSQL 18.4（<DB_HOST>:<DB_PORT>/crypthub（见 .env））+ 智谱 API（glm-4-flash / embedding-3@512 维）
本地：uvicorn + worker + fakeredis（无 docker 开发方案，scripts/dev_redis.py）

**新增偏差（联调确认，已实现）**：

1. 目标库无 pgvector 扩展 → embedding 存 `real[]`，向量检索改为两阶段
   （先取向量 Python 侧精确余弦取 top-8，再取整行 RRF 融合）——检索质量不变，
   部署不再要求 pgvector（compose 可用普通 postgres:16）。
2. 目标库无 Redis → 本地开发用 fakeredis TCP 服务器；worker 循环对
   TimeoutError/ConnectionError 做了免疫（瞬时错误不杀守护进程）。

**端到端冒烟（scripts/smoke_e2e.py，模拟浏览器走全链路）25/25 通过**，
覆盖：引导→建号(组织密钥)→挑战登录→错误密码拒绝→上传→去重 409→
worker 索引(真实 embedding)→兜底扫描(3 条待认领)→混合检索→AI 问答(真实 LLM+引用)→
解锁→建条目(AAD)→reveal 解密闭环→lock 拦截→第二用户→跨用户 403→审计全覆盖。

## 功能追加：多级目录（2026-11-11）

文档区与密钥区均支持多级目录归类（超出 v1.1 设计范围的增强）：

- 新增 `folders` 表：`parent_id` 自引用多级，`kind` 区分 doc/secret 两棵独立树；
  同目录同名唯一（表达式唯一索引），层级上限 10 级，移动禁止进入自身子树（环检测）。
- **文档目录**：全员共享树，`documents.folder_id` 归档；删除目录时子目录级联删除，
  文档自动回到未归档（FK ON DELETE SET NULL）。
- **密钥目录**：每人私有树（`owner_id`），归档位置存在授权行
  `secret_grants.folder_id` —— 同一条密钥 owner 与被授权人可各自归档，互不影响。
- API：`GET/POST /folders`、`PATCH/DELETE /folders/{id}`、
  `PATCH /documents/{id}`(folder_id)、`PATCH /secrets/{sid}/folder`；
  前端两页共用 FolderTree 组件 + 目录选择弹窗，列表为客户端过滤。
- 运维注意：**改动 schema（加列/表）后需重启 worker**——长连接 asyncpg 的
  预编译语句缓存会因 schema 变更失效（首次访问该语句的文档索引会失败一次，
  SQLAlchemy 随后自动整体失效缓存，自愈）。

## 缺陷修复：索引任务丢失导致文档永远"查不到"（2026-11-12）

- 现象：用户上传的《01-报文与签名》一直 status=processing、chunks=0，
  搜索与 AI 问答都无结果；队列里任务也没了——任务在队列中丢失后文档
  永远卡死（内存型 Redis 重启清空队列、坏 JSON 任务被静默丢弃等场景）。
- 修复：worker 增加自愈 heal_stale_docs()——空闲心跳每 60s 扫描
  status=processing 且 updated_at 超过 10 分钟的文档，UPDATE updated_at=now()
  （兼作"已补发"标记，再丢再补）后重新入队；worker 启动首个空闲心跳立即执行。
- worker 输出改落 logs/worker.log（此前无日志文件，故障无从追溯）。
- 修复后该文档自动补发索引成功（12 chunks × 512 维），真实查询验证：
  向量 top1 命中对应章节（0.64~0.70），关键词「报文|签名」命中 5 块，RRF 融合正常。

## 用户名+密码成对认领（2026-11-12）

## 重复上传改为原地更新（2026-11-12）

- 原行为：sha256 重复直接 409「内容重复，如需更新请先删除」；脱敏规则升级后
  重传同一文件（红字内容变了→sha 不同）还会同题新建一份。
- 新行为（POST /documents 去重逻辑重写）：
  ① sha256 全局一致 → 原地更新该文档（字节相同复用旧文件不重复落盘）；
  ② 同一用户存在同名文档（内容不同）→ 同样原地更新（换新文件、删旧文件、重建索引）。
  更新时清理旧 chunks 与该文档未认领的 pending（已认领的保留作审计），
  folder_id 表单未选时保留原目录，status 重置 processing、error 清空、
  enqueue 重建索引，审计 doc_updated（update_reason: same_sha256/re_upload），
  响应带 updated: true；前端 toast 提示「文档已存在，已更新并重建索引」。
- 验证：compileall OK、pytest 30 passed、tsc 0、vitest 70/70、build ok，
  API 重启后 healthz ok/db/redis true。
