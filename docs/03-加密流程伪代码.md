# 加密流程伪代码（实现版）

> 对应设计方案 v1.1 第 4 节。前端实现于 `frontend/src/crypto/`，
> Python 镜像实现于 `backend/app/mirror_crypto.py`（供离线恢复脚本与互操作测试）。
> 本文与代码的差异点均已注明。编码约定：字节 ↔ b64（标准 base64）；文本为 UTF-8。

## 0. 算法与参数（锁定）

| 用途 | 算法 | 参数 |
| --- | --- | --- |
| 口令 KDF | Argon2id | m=64MiB, t=3, p=1, 输出 32B |
| 子密钥派生 | HKDF-SHA256 | 输出 32B，salt/info 见下 |
| 对象加密 | AES-256-GCM | 随机 12B nonce，AAD 必填 |
| 非对称包装 | ECIES(X25519) | ephemeral X25519 + HKDF + AES-GCM |
| 签名域分隔 | AAD | 每种密文固定前缀 + 上下文 id |

```text
// ---------- 派生 ----------
rootKeyAuth = Argon2id(MP, salt_auth)            // 登录域
rootKeyEnc  = Argon2id(MP, salt_enc)             // 数据域（与上独立 salt）
authKey     = HKDF-SHA256(ikm=rootKeyAuth, salt="kb:auth",  info="auth",  len=32)
authProofKey= HKDF-SHA256(ikm=authKey,     salt="kb:ap",    info="ap",    len=32)  // 服务端唯一可见
encKey      = HKDF-SHA256(ikm=rootKeyEnc,  salt="kb:enc",   info="enc",   len=32)  // 永不出浏览器
rkKey       = Argon2id(RK, rk_salt)                                                   // 个人恢复码域

// ---------- AEAD 包装（对称） ----------
wrap(key, plaintext, aad) = nonce(12) ‖ AES-256-GCM-SEAL(key, nonce, plaintext, aad)
unwrap(key, blob, aad)    = AES-256-GCM-OPEN(key, blob[0:12], blob[12:], aad)  // 失败即抛错

// ---------- ECIES 信封（非对称包装，用于 DEK/组织私钥） ----------
sealFor(recipientPub, plaintext, aad):
    eph      = X25519.keygen()
    ss       = X25519(eph.priv, recipientPub)
    key      = HKDF-SHA256(ikm=ss, salt=eph.pub ‖ recipientPub, info="kb:seal:" ‖ aad, len=32)
    return    eph.pub ‖ nonce(12) ‖ AES-GCM-SEAL(key, nonce, plaintext, aad)
openSealed(myPriv, blob, aad):  // 对偶操作
    ss = X25519(myPriv, blob[0:32]); key = HKDF(...同上...); return AES-GCM-OPEN(...)
```

> **与设计文档的实现差异（已确认更优）**：设计 4.5 写"私钥用管理员 encKey 包装"，
> 实现改为"组织私钥用各管理员**公钥** ECIES 再包一份"（`org_recovery_delegates`）。
> 安全域等价（管理员 encKey → 解出自己的私钥 → 才能解组织私钥），但任意管理员都可代为恢复，
> 不限于引导管理员。org_recovery 表结构相应调整，DDL 已同步。

## 1. 建号（管理员开号 → 用户完成设置）

```text
// 客户端（setup 页，凭开号令牌 setupToken）
salt_auth, salt_enc, rk_salt = random(16)×3
authProofKey = 派生链(MP …)            // 上节
encKey       = 派生链(MP …)
local_check  = wrap(encKey, "vault-check-v1", aad="kb:local-check")
userPriv, userPub = X25519.keygen()
priv_wrapped     = wrap(encKey, userPriv, aad="kb:user-priv:" ‖ userId)   // userId 注册后回填
priv_rk_wrapped  = wrap(rkKey,  userPriv, aad="kb:user-priv-rk")
RK = base32(random(32))               // 展示一次，用户抄写
POST /auth/setup {setupToken, username可见信息, salt_auth, salt_enc, authProofKey,
                  local_check, userPub, priv_wrapped, rk_salt, priv_rk_wrapped}
// 服务端：全程未见 MP / encKey / 私钥明文
```

**引导（首管理员）额外做**：生成组织密钥对与离线恢复码；上传
`org_recovery{public_key, offline_salt, org_priv_offline_wrapped}` 与
`org_recovery_delegates{sealed: ECIES(自己的公钥, org_priv)}`；
下载**离线恢复包**（JSON：offline_salt + wrapped + 参数 + 使用说明）打印入柜。

## 2. 登录（挑战-应答，防重放；登录 ≠ 解锁）

```text
C→S POST /auth/challenge {username}
S    challenge = random(32)hex；redis[ch:challengeId]=userId TTL 120s
C    proof = HMAC-SHA256(authProofKey, challenge)
C→S POST /auth/login {challengeId, proof}
S    HMAC-SHA256(db.auth_verifier, challenge) 恒等比较 → 发会话 Cookie（HttpOnly）
S    限流：每 username+ip 15 分钟 5 次失败锁定
```

## 3. 解锁密钥区（纯前端行为，服务端只记录标志）

```text
encKey = 派生链(再次输入的 MP, salt_enc)     // 需与登录分开输入，动作独立
plain  = unwrap(encKey, local_check_ct, aad="kb:local-check")  // 成功即解锁
encKey、解出的 userPriv 只存 JS 内存（刷新即失，重新解锁）
POST /secrets/unlock   // 仅置会话标志（服务端无法验证真伪，见设计 4.2 说明）
POST /secrets/lock     // 置反，前端同时清内存
```

## 4. 条目加密形态（服务端只搬密文）

```text
DEK = random(32)
content_ct      = AES-GCM-SEAL(DEK, 内容JSON, aad="kb:secret:" ‖ secretId)
dek_wrapped_org = sealFor(orgPub, DEK, aad="kb:org-dek:" ‖ secretId)
grant(owner)    = sealFor(ownerPub, DEK, aad="kb:dek:" ‖ secretId ‖ ":" ‖ ownerId)
// 内容JSON：{username,password,url,tokens,notes,custom[]} —— 字段自由，前端解释
```

## 5. 查看密钥（reveal）

```text
S GET /secrets/{id}/reveal → {content_ct, wrapped_dek(请求者的), version}   // 限流 20/min + 审计
C plain = unwrap(DEK链: encKey→userPriv→openSealed(wrapped_dek)→DEK, content_ct, aad)
```

## 6. 共享 / 撤销 / 轮换

```text
共享：C 已持 DEK → sealFor(对方公钥, DEK, aad="kb:dek:…") → POST grants
撤销：S 删 grant 行（前端提示：已看过明文收不回，敏感条目应轮换）
轮换：C 生成 DEK' → 新 content_ct → 对 owner+全部 grantee+org 重新包装
      → PUT secrets/{id}/rotate {content_ct, wrapped_deks{userId:seal}, dek_wrapped_org,
         old:{content_ct, wrapped_deks}}   // 旧件归档 secret_versions
```

## 7. 组织恢复 / 离职交接（同一组端点，见设计 4.5/4.6）

```text
① admin: POST /admin/recovery/prepare {reason}        // 审计+通知, 返回 org_sealed_to_admin
② admin: encKey→userPriv→openSealed(org_sealed) → orgPriv（内存）
③ admin: POST /admin/recovery/entries {user_id}       // 目标用户全部条目: 密文+org包装DEK
④ admin: 前端逐条解开；选接手人 → 逐条 sealFor(接手人公钥, DEK)
⑤ admin: POST /admin/recovery/regrant {reason, successor_id, transfer, items[]}
         → 建授权行 / 转移 owner → 审计 + 通知 owner 与接手人
离线路径：orgPriv = unwrap(Argon2id(离线码, offline_salt), org_priv_offline_wrapped)
          → scripts/offline_recover.py 对 pg_dump 恢复库离线解密全部条目
```

## 8. 个人恢复码（新设备找回）

```text
新设备登录后（不知 MP 亦可）：输入 RK → rkKey=Argon2id(RK, rk_salt)
→ userPriv = unwrap(rkKey, priv_rk_wrapped, aad="kb:user-priv-rk")
→ 请求 reveal 各授权条目 → openSealed → 明文。RK 是 32B 随机数，离线爆破不可行。
```

## 9. 不变量（任何改动不得破坏）

1. `encKey`/用户私钥/DEK/条目明文永不离开浏览器（离线恢复脚本除外，其运行在管理员机器上）。
2. 服务端持久化数据中不存在任何能直接解开条目的密钥材料。
3. 每种密文 AAD 固定且互异，防密文挪用（换表重放）。
4. 所有 KDF 输出 32B；所有随机数来自 CSPRNG。
